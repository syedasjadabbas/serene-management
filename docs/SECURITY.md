# SERENE MANAGEMENT — Security overview

This is an index of the security controls and where each is implemented and verified. Details live in the referenced documents. Audit status and open findings are in [PRODUCTION_READINESS.md](PRODUCTION_READINESS.md).

## Controls

| Control             | Implementation                                                                                                                                                                                                                                                                                                                 | Verified by                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Authentication      | Argon2 password hashes. Short-lived signed access token (HS256; algorithm, issuer and audience pinned) plus a rotating refresh token. The session, user, organization and property state is re-read from PostgreSQL on every request; nothing is cached across a revocation (`lib/auth`, `modules/identity`, `modules/access`) | Integration tests; cross-instance session tests (SCALABILITY §37.5, §38.14) |
| Session revocation  | Logout, password change or reset, and disabling a user revoke sessions. Live streams end through database triggers                                                                                                                                                                                                             | Tests; UAT step 20                                                          |
| Login protection    | Per-account and per-IP limits shared through PostgreSQL; lockout; one argon2 run on every path; one error message for every failure                                                                                                                                                                                            | `rate-limit` tests; regression (PRODUCTION_READINESS §7)                    |
| RBAC and isolation  | Permissions are checked server-side in every route or service; the property id comes from the path only; records are loaded scoped to the property or organization; escalation guards on role grants (RBAC.md)                                                                                                                 | Integration tests; organization, property and cross-instance checks         |
| Financial access    | Amounts and ledgers need `billing:read` / `reports:financial`; financial values are redacted in audit trails without them                                                                                                                                                                                                      | Tests (D54)                                                                 |
| Guest personal data | Contact data needs `guests:read` (profiles, audit trails, stay details; D56)                                                                                                                                                                                                                                                   | `front-desk.test.ts`                                                        |
| CSRF                | Writes need an `Origin` equal to `APP_URL` in production; cookies are `SameSite`, `__Host-`/`__Secure-`                                                                                                                                                                                                                        | Tests; regression                                                           |
| Client IP           | Only the right-most `TRUSTED_PROXY_HOPS` entries of `X-Forwarded-For` are trusted; `X-Real-IP` and `Forwarded` are ignored (D44)                                                                                                                                                                                               | Spoofing tests through the proxy chain                                      |
| Input               | Strict Zod schemas on every route; bounded arrays, strings and pagination; parameterised SQL; JSON bodies ≤ 1 MiB (413)                                                                                                                                                                                                        | Tests; `request-limits.test.ts`                                             |
| Output and errors   | Clients get only `AppError` messages; logs record database errors by code and redact e-mails, tokens and connection strings (G12)                                                                                                                                                                                              | `log-redaction` tests                                                       |
| Headers             | Nonce CSP with `strict-dynamic`, HSTS, `nosniff`, `X-Frame-Options: DENY`, COOP, `Permissions-Policy`                                                                                                                                                                                                                          | `http-hardening` tests                                                      |
| Ledgers and audit   | Append-only triggers and TRUNCATE guards on `folio_items`, `audit_logs`, `room_status_history`, `cash_movements`; every command is audited                                                                                                                                                                                     | Database tests; `ops:db-check`                                              |
| Realtime            | Streams are authorized per property and topic; payloads carry topic names only; access changes end streams                                                                                                                                                                                                                     | Realtime tests; cross-instance checks                                       |
| Background jobs     | A job is visible only to its starter, at a property they can still reach; payloads are never exposed; permission re-checked at execution                                                                                                                                                                                       | Job tests                                                                   |
| Offline             | Minimised IndexedDB snapshot, 24 h expiry, wiped on sign-out or user change; `/offline` confirms the session with the server before showing anything (OFFLINE_ARCHITECTURE §J)                                                                                                                                                 | Unit tests; browser check (PRODUCTION_READINESS P1-2)                       |
| Metrics             | `/api/metrics` 404 without `METRICS_TOKEN`; labels are bounded and never personal (OPERATIONS §11)                                                                                                                                                                                                                             | Observability tests                                                         |
| Secrets             | Environment validation refuses placeholder or weak secrets, http `APP_URL` and a missing `TRUSTED_PROXY_HOPS` in production (`lib/env.ts`)                                                                                                                                                                                     | `env` tests                                                                 |

## Operator responsibilities

- Keep `.env` and backups out of version control and off shared storage; backups are encrypted and kept off the host (OPERATIONS §2).
- Run the application as the runtime role, not as the schema owner (OPERATIONS §4).
- Make instances reachable only through the proxy chain, and set `TRUSTED_PROXY_HOPS` to its exact length (DEPLOYMENT §7).
- On shared workstations, staff sign out at the end of a shift.
- Rotating `AUTH_REFRESH_TOKEN_SECRET` signs everyone out (DEPLOYMENT §8).

## Known limitations

See PRODUCTION_READINESS §3. Notably:

- refresh-token reuse is detected for one generation only (P2-1, a post-handover enhancement);
- there is no payment-provider integration, so no card data is ever handled (payments are recorded only).
